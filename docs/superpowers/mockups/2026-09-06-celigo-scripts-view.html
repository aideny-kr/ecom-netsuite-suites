Decisions baked into this mock

  • Account-wide, beside the flow map. Agreed today. A family is Celigo's clone lineage (its dedup_key), never a name: eight separate single-copy families are all called inventory_sync_filter, and the list says so rather than merging them.
  • Versions by content, original by lineage. Letters come from content hashes ordered by first appearance. "Original" is Celigo's clone root, shown as a mark on whichever version it currently has.
  • Compare any two versions, default oldest → original, through the workspace's existing Monaco diff viewer (read-only, side by side or inline). No new dependency.
  • Search is names, functions, and flows, client-side. Agreed today. Content search is a later backend slice.
  • The drawer stays. It is the in-flow quick look (#223, #224); the Scripts view is where the whole family lives. The link between them is now real in both directions.
  • Human-only, as before. Script content never reaches the assistant or RAG (the N2 rule and its AST test stay in force). The new endpoint is served the way the drawer's is, and the chat tools never gain a content path.
  • Errors per site reuse the flow map's open-error counts and honesty stamp (#221); a site with an unchecked flow shows "not checked", never 0.

What it takes

  • Backend T2 · one family-list endpoint over the existing clone grouping (name, kind, function, copies, versions, sites, flows, integrations, error rollup, no content) and one family-detail endpoint (members with version letters, dates, sizes, content for the selected copies, every site with integration, flow, step name, role, adaptor, paused flag, open errors). Both gated on the flow-map connection like the drawer's endpoint.
  • Frontend T1 · the Scripts surface (toggle, tiles, list pane with search and chips, detail pane with versions strip, code, compare, where-used), the route params (tab=scripts, script, copy, integration), the drawer link, the integration Scripts tab, the ⌥-click on the canvas chip.
  • Tests first, including a page-level assertion that nothing on this surface can write to Celigo, and the existing AST guard extended to the new module.
  • Out of scope now: content search, a change feed across syncs, "what does this script do" in words, editing or deploying scripts (never from this surface).
  • Rough size: backend ~1.5 days, frontend ~3 days, live check on staging against these exact families.
