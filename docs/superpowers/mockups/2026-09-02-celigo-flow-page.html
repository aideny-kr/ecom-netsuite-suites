Two pills, not one adjective. Celigo's tile says "Success". Here the first pill is the error fact and carries the time it was checked, so a zero is a claim with a timestamp, not a decoration. The second pill is the schedule fact (on time · stalled? · on demand only · all paused); a scheduled flow that quietly stopped shows no errors — absence is not success — so the second pill is the one that would catch it. The bubble. Eyebrow = Celigo's own type vocabulary (Source · Lookup · Destination) plus the app family. Title = the name you typed in Celigo once it is synced; until then the honest fallback is what the step does — add salesorder, lookup customer · search 5090 — and "name not synced" for HTTP steps. Then the affordances Celigo hangs on the connector line, in Celigo's own per-side order (sources: transform · hooks · output filter; destinations: input filter · NetSuite mapping · response mapping · hooks) so an absent one is visible and comparable across bubbles. Three chip states: configured, looked-and-none (hollow), cannot-say (dashed) — the import's NetSuite field mapping is dashed on every destination because the sync drops it. A hook chip carries the function name and the script's clone state: ×1 one copy; C/3 this step runs copy C of a family with three differing versions, and the amber dot says so without a tooltip.

Routers and lanes, as Celigo declares them. This flow chains two routers: router 1 has one branch whose nextRouterId points at router 2, which routes on input filters to the first matching branch. Branch names ("Framework Intl", "Framework Inc"), the rule, the routing mode and the chain are already in the synced flow object; they only need projecting into the API. 8 of the 122 flows chain routers this way and 19 have a router at all, so the chained layout is built and tested, not deferred. Layout is deterministic — ranks left to right: sources · router · lookup · router · branch lanes — so a refetch never reshuffles. Navigation

  • One page, five URL params. /workspace?surface=celigo (tiles) · &integration= (flows table, &tab=) · &flow= (full page) · &step= and &script= (selection, drawer). Every state is a link; refresh keeps it; Back walks up. surface moves from React state into the URL — today a refresh drops you back to Files.
  • One writer for the URL. The new route hook is the only thing that writes these params; it clears ?file= when entering the Celigo surface and vice versa, and the existing file/workspace effect ignores Celigo params. With the feature flag off, ?surface=celigo renders Files.
  • Breadcrumb at every level; the navigator hops between sibling flows without going up. ⌘B collapses it (the page-level handler branches on surface — today it is a silent no-op here). ⌘K is a real palette over all 122 flows, each result carrying its health dot and integration. Esc clears the selection; a second Esc closes the drawer.
  • The Celigo branch of the workspace page mounts its own panel group (rail · canvas · inspector) with its own persisted-layout id. The Files group — tree, changesets, diff, Deploy — is never in the tree on this branch. That guarantee gets a DOM-level page test, not a comment.
  • Nested routes (/workspace/celigo/[flowId]) were considered and dropped: they would need a second layout to carry the toolbar and the feature gate.

What it takes · 13 days, +1.5 with names

  • Backend, T1, ~3 d — step fact fields · router/branch projection · per-step error counts + error filters · integration summary · changes route · flow-level writes. Tests first; the layout gets a fixture matrix (single source→destination, top-level chain, one router with 2 lanes, empty lane, chained routers, duplicate step across branches, 0 steps).
  • Frontend, ~10 d — URL state + breadcrumb (0.5) · tiles, list, filters, palette (1.5) · integration page + tabs + step drawer (1) · flow page shell in the panel group + rail (1) · canvas: layered layout, bubble, router, lanes, fit/zoom (2.5) · inspector tabs + Overview (1.5) · script drawer from the dialog (0.5) · stall heuristic + states (1) · tests, seeded Celigo fixture for e2e, retire the old map (1). The helpers being reused are module-private today and get extracted once.
  • Names sync, T2, ~1.5 d — one column, one backfill parameter, one migration. Recommended in the same train (decision 1).
  • Not included — connections (~2 d + live probe), NetSuite field mapping (~1 d), run history (~3 d).
  • Tier: T2 gate for the PR either way (workspace shell change, new routes over customer JavaScript and error payloads; a migration if names ride along). Budget two gate rounds, not one.

Risks

  • Stall detection is a heuristic on the one cron shape seen live. It must say "stalled?" with the question mark, use sync time not wall time, and go silent on any cron it does not parse and on listener-driven flows.
  • Zero live errors means the error state ships against a fixture — the recurring fixture-vs-live blind spot. Mitigation: the 17 Aug payload as the fixture, the cross-surface count assertion in the seeded e2e, and "untested live" on the PR.
  • Two counts of open errors exist once Celigo's own number is projected: ours from stored rows, Celigo's from the flow object. The pill shows ours; a disagreement is captioned, never averaged.
  • Lookups inside imports are dropped by the sync (a different thing from the lookup steps drawn here). A canvas cannot mark what it cannot see; the spec table names the gap.
  • reactflow's stylesheet is global once loaded — lazy-load the canvas behind the Celigo branch and scope its CSS so Files users never pay for it.
  • The AI description is inherited on clone and can describe an ancestor, as it does here. It is shown as Celigo's text with that caption, never as our summary; the derived sentence above it is ours.
