Celigo Scripts view

You said the map "doesn't really show scripts". Two things were true. The sync had never stored a single script body, because Celigo's list omits it; that fix is in PR #217. And even with source, scripts were reachable only through an amber chip inside an expanded flow, and 51 of the 129 production scripts are attached nowhere, so nothing could ever show them.

This is the design a three-angle panel converged on (3 of 3 judges): a Scripts view beside the flow map, every script collapsed into its clone family, grouped by what kind of site runs it, with the source and a where-used table on one screen. Every name and number below is from your Framework account as of this morning's sync, except the two items marked example.

Decisions to confirm

  1. This layout. Scripts as a sibling view of the flow map, family-collapsed, split pane, two-way links. The alternatives the panel scored lower: scripts mounted as a read-only celigo/ tree in the Files explorer, and a per-flow wiring diagram with code beside it.
  2. Keep the assistant out of script content (the standing N2 decision). This view is human-only and its search is plain text matching, not embeddings. Reversing that is a separate call.
  3. Error pills on sites need the live error vocabulary first; your account has 0 open errors today, so this ships as the design above and lights up when errors exist.
  4. Tier. New endpoints over customer JavaScript. I'd gate the backend half as T2 again.

What it takes

  • Backend ~2.5 days: one family-list endpoint built on the existing clone grouping, richer where-used rows (integration name, step record and operation, paused flag), plain-text content search capped and never logged.
  • Frontend ~4 days: the Scripts view and its list and detail panes, the sub-toggle, the flow-map handoffs, retiring the current script dialog.
  • Tests first, including the page-level assertion that nothing on the Celigo surface can deploy or push — a guarantee that today lives in a comment, not a test.
  • Prerequisite: PR #217 (script bodies) merged and one sync run.

What the panel could not answer yet

  • "What does this script do" in words. Only 42 of 122 flows carry a Celigo description; everything else is read from the JavaScript.
  • A change feed. Config drift is already recorded per sync; it is empty for now and would be the reason to open this every day.
  • Stale sites. A shrunk flow can leave a where-used row that no longer exists in Celigo; a "seen in last sync" marker fixes it.
  • Step names. Celigo's own export and import names are not stored yet, so steps read as "Source · HTTPExport" rather than the name you gave them.
